# 機能要件

TODOを `localStorage` に保存し、ブラウザーの再読込後に復元する。

## 前提

- TICKET-001・002の実装と確認を済ませ、既存機能を維持する。
- 単一タブで操作する。サーバーやデータベースは使わない。
- 保存キーは `dqd-todo-list-v1`。絞り込みは保存せず、起動時は「すべて」にする。

## 実装する機能

- 追加・完了切り替え・削除のたびに、数値のバージョン `1` とTODO配列を含むJSONを保存する。
- 起動時に復元する。データがなければ空の一覧で始める。
- 読込に失敗したら通知し、元のデータを残して保存を無効にする。メモリ内では操作できる。
- 保存に失敗したら操作結果を画面に残し、再読込で失われる可能性を通知する。次の変更時に再試行する。

# 個別合格条件

## CM-001

- TICKET-001とTICKET-002の確認項目を再実行する。

## UI-001

- 375px、768px、1440pxの各表示幅で、保存エラーの通知が読め、既存の操作を継続できる。

## FE-003

- AとBを登録してBを完了にし、再読込しても、ID、内容、完了状態、順序が復元される。
- Aを削除して再読込すると、Aは復元されずBだけが残る。
- JSONの破損、未対応のバージョン、重複ID、不正な内容・完了状態を持つデータは、読込エラーとして扱う。
- 読込エラー時に操作しても、元の保存データは上書きされない。
- 書込不能時もメモリ内の操作を継続でき、保存失敗の通知が表示される。
- 保存可能になった後の変更で保存が成功すれば、保存失敗の通知が解除される。
